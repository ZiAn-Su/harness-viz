# 节点执行记录：采集边界

本表对应当前固定的 OpenCode 1.18.34、Codex 0.160.0。按用户要求，继续使用原版 CLI，不增加上游源码埋点、不重新编译 CLI。页面中一条执行记录关联一次有明确身份的工作；原始事件另行保留。

## 共用展示

运行准备、模型、工具、权限和已观测返回等记录均按「执行信息 → 本次输入 → 实际处理 → 本次结果」展开。模型继续保留原始请求/响应、模板和下载；工具保留完整参数、输出、错误和原生状态。

四个标题下必须是可直接阅读的实际内容：文件路径与正文、命令与退出码、修改前后内容、权限范围及选择、模型回答或工具提案；不能只把完整对象格式化后展示。原始结构放在折叠技术详情，长正文另可继续阅读。Codex返回节点可关联同一run/session/用户轮次的原生已完成回答和文件活动，单独标明来源，不当作完成报告自身字段或独立正确性证明。

- 原生提供 time.start/time.end 或 trace wall_time 时使用其值。
- 仅提供开始/结束事件接收时间的交互，应标明接收边界；不能称为原生函数精确耗时。
- 只有终态报告时，只展示已知结束边界，开始与耗时保持未采集。
- 同一工具调用、权限 requestID、压缩 compaction_request_id 的更新合并到同一记录，不新增执行次数。
- 取消与失败分别显示；取消时保留部分响应，不能据此认定主任务失败。

## OpenCode

| 节点 | 可采集依据 | 当前记录范围 |
|---|---|---|
| 开始任务 `ui` | 本地任务准入 `viz.run` | 本条用户输入被任务入口接受；只有准入点，不补提交耗时 |
| 运行准备 `server` | `viz.preparation` + 精确 messageID 的原生保存确认 | 已批准的入口准备样例，每次用户提交一条 |
| 调用模型 `llm` | SDK原协议请求/响应捕获 | 本次请求到响应终态；保留原文与部分错误/取消内容 |
| 执行工具 `tool` | 原生 tool part + callID + state.time | pending 不计执行，running/终态更新同一工具调用 |
| 管理子任务 `sub` | 原生 task 工具 part/callID、明确父子会话关系 | 本次管理调用及子会话内已观测活动；管理返回不等于后台任务结束 |
| 汇总反馈 `exec` | 原生工具终态 part | 工具反馈及错误已返回；不是独立数据库写入函数计时 |
| 环境与权限 `sandbox` | permission.asked/replied + requestID/sessionID | 一次询问/答复合成一条；不推断后续工具是否执行 |
| 执行压缩 `subflow2` | session.compacted | 原生完成报告；开始/完整耗时未知，不猜触发入口 |
| 本次处理退出 `done` | 原生消息处理接口返回 `viz.prompt.returned` | 返回内容、错误与返回边界；不猜内部退出谓词 |
| 读取历史 `loop` | 原版无对应函数执行事件；可捕获模型请求 | 只显示所选时点的用户要求、助手已有进度、最近可关联反馈摘要；未知字段省略。内部读取及待办队列仍未采集，不用消息数或请求数补执行次数 |
| 请求已完成? `decide`、取出哪类待办? `subflow1`、容量不足? `subflow3` | 原版无对应判断事件 | 未采集；不从 finish/token/任务标记推导实际分支 |
| 客户端派发 `decide2`、工具类别 `delegate` | 只有输出/执行证据，无该判断函数事件 | 未采集判断过程，不能拿工具输出充作判断记录 |
| 执行指定任务 `pre-sub`、安排压缩 `schedule` | 持久化标记本身不提供执行入口 | 未采集执行；标记仍保留原始日志 |
| 压缩返回判断 `compact-result`、本轮处理结果 `outcome` | 原版无内部返回判断事件 | 未采集，不从相邻事件补造判断结果 |

## Codex

| 节点 | 可采集依据 | 当前记录范围 |
|---|---|---|
| 开始任务 `c-ui` | 本地任务准入 | 本条用户输入与会话方式 |
| 运行准备 `c-server` | 入口准备 + 原生 turn.started | 启动/恢复及原生接收确认，不把进程/线程状态分成多次准备 |
| 调用模型 `c-llm` | inference_started/completed/failed/cancelled | 真实请求/终态、原文与用量；取消保持取消 |
| 执行工具 `c-tool` | exec JSONL 工具 item 身份 | 原始命令/MCP/文件/搜索活动；无原生时间时只标接收时间，不编耗时 |
| 管理子任务 `c-sub` | collab_tool_call + 明确线程关系 | 本次管理调用与原生返回的子任务状态，不推断所有子任务结束 |
| 汇总反馈 `c-feedback` | 已完成工具 item | 实际输出、退出码与错误；不补数据库写回时长 |
| 整理上下文 `c-context` | compaction_request_id 对应原生请求/返回；可捕获模型请求 | 可记录远程整理请求及原生起止；无 phase 时不分配到 pre/mid/post。另显示用户要求及已有进度的精简摘要；响应链仅完整且明确关联时用于补全，不把摘要算作内部读取执行 |
| 本轮返回 `c-done` | turn.completed/failed | 完成/失败报告与用量；退出判断/维护时长未知 |
| 环境与权限 `c-sandbox` | 启动配置不是工具审批事件 | 配置留原始日志；没有明确询问/答复不能补权限执行记录 |
| 整理上下文内部的 build_prompt 本身（非独立图节点） | 请求边界不提供其函数入口/出口 | 未采集；已捕获请求和重建上下文仍在模型详情 |
| 需切换上下文? `c-budget`、还需处理? `c-decide` | 原版无对应判断执行事件 | 未采集 |
| 执行压缩 `c-compact`、启动检查阻断? `c-compact-next` | trace不提供相应阶段或hook执行边界 | 不把无phase的compaction请求当作这些节点的执行 |
| 派发 `c-decide2`、类别 `c-delegate` | 处理器活动不等于独立判断函数 | 未采集判断 |
| 收尾结果 `c-stop`、收尾维护 `c-finalize` | 当前trace不足以确认这些内部步骤 | 未采集，保留源码说明 |

以上「未采集」不表示步骤没有执行。保持原版时，不能以页面重建、读取数据库副本或推测条件的方式伪装成原生执行采集。
